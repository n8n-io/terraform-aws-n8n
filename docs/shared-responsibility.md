# Shared responsibility

This module creates and configures an opinionated slice of AWS
infrastructure for n8n: EKS, an ALB Ingress, an RDS PostgreSQL instance,
ElastiCache Redis, an S3 bucket, and the n8n Helm release. It does not, and
is not intended to, run the whole platform for you. This page collects the
ownership boundaries that are otherwise scattered across the README's "Out
of scope" and "Support" sections, individual variable descriptions, and
several other docs, into one table so a platform partner pricing a build on
top of the module can find every gap in one place.

Read this alongside
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md)
and the README's [Customer-managed infrastructure](../README.md#customer-managed-infrastructure)
table, which document the caller-managed *layers* (RDS, ElastiCache, EKS,
S3, KMS keys, the EBS CSI driver, the cluster controllers, and the external
worker fleet) this module can hand off entirely. The rows
below cover responsibilities that exist regardless of which layer ownership
mode is selected.

| Area | What the module does | What the caller owns | Related input / doc |
|---|---|---|---|
| Cluster security add-ons and policy | With `create_eks = true` (the default), creates the EKS cluster and its node group, envelope-encrypts Kubernetes Secrets with a Customer Managed KMS key by default (`eks_secrets_encryption_enabled`), and lets the caller restrict or disable the public API endpoint (`cluster_endpoint_public_access`, `cluster_endpoint_public_access_cidrs`, `cluster_endpoint_private_access`). With `create_eks = false`, it attaches to an existing cluster and manages none of these. | GuardDuty EKS Runtime Monitoring, Security Hub, and Pod Security admission policy are not enabled by the module and must be turned on separately (e.g. via `aws guardduty`/`aws securityhub`, or a `kubernetes_*` policy resource outside this module). On a module-created cluster, the public endpoint is reachable from `0.0.0.0/0` by default; narrow or close it with the inputs above. On an existing cluster (`create_eks = false`), node groups, Secrets encryption, and API endpoint exposure belong to the cluster owner. | `create_eks`, `eks_secrets_encryption_enabled`, `cluster_endpoint_public_access`, `cluster_endpoint_public_access_cidrs`, `cluster_endpoint_private_access`; [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md) |
| Network egress and DNS | Uses a caller-provided VPC and subnets (VPC creation is explicitly [out of scope](../README.md#out-of-scope)); when `create_ingress = true`, creates an ALB Ingress with a public or internal frontend; and when `route53_zone_id` is set, issues the ACM certificate and, if `create_ingress = true` as well, creates the Route 53 alias record(s) itself. | No NAT gateway, egress firewall, or VPC endpoint is created, outbound traffic from the cluster depends entirely on the VPC the caller brings. With a caller-supplied `certificate_arn` instead of `route53_zone_id`, DNS and certificate issuance are the caller's responsibility; see `examples/cloudflare/` and `examples/godaddy/` for that path. A caller bringing its own Ingress (`create_ingress = false`) with `route53_zone_id` set still gets the ACM certificate from the module but owns the alias record itself, since there is no module-managed ALB to point it at. DNS resolution for an externally supplied PostgreSQL or Redis endpoint (`create_database = false` / `create_elasticache = false`) is also the caller's. | `route53_zone_id`, `certificate_arn`; [`examples/small/`](../examples/small/), [`examples/cloudflare/`](../examples/cloudflare/), [`examples/godaddy/`](../examples/godaddy/) |
| Secrets and Terraform state | Generates, as Terraform-managed values: the RDS admin password (`random_password.db_password`, always generated, but only used when `create_database = true`); the n8n encryption key when neither `n8n_encryption_key` nor `n8n_encryption_key_secret_ref` is set; the ElastiCache AUTH token when `create_elasticache = true`, `redis_transit_encryption_enabled = true`, and `redis_transit_encryption_mode = "required"`; and the task-runner token. | Every generated or caller-supplied value the module does not receive through a `*_secret_ref` lands in Terraform state: `random_password.db_password` (on every path, including `create_database = false`), `db_password` when `create_database = false` and `db_password_secret_ref` is unset, `n8n_encryption_key` unless `n8n_encryption_key_secret_ref` is set, `n8n_license_key` when `n8n_license_key_secret_ref` is unset, `random_password.task_runner_token` (always module-generated, no secret-ref alternative), `random_password.redis_auth_token` under the three conditions above, `redis_auth_token` when `create_elasticache = false` and `redis_auth_token_secret_ref` is unset, `n8n_otel_exporter_otlp_headers` when set with `n8n_otel_enabled = true`, and `n8n_log_streaming_destinations` when set with `n8n_log_streaming_managed_by_env = true` (both are rendered as literal pod environment variables). Securing the Terraform state backend (encryption at rest, restricted access) is the caller's responsibility in every mode. Route the license key, encryption key, credentials-overwrite payload, external database password, and external Redis AUTH token through `n8n_license_key_secret_ref`, `n8n_encryption_key_secret_ref`, `n8n_credentials_overwrite_secret_ref`, `db_password_secret_ref` (external database path only, `create_database = false`), and `redis_auth_token_secret_ref` (external Redis path only, `create_elasticache = false`) to keep those specific values out of state. | [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md); README [Secrets](../README.md#secrets) |
| Backup and restore | With `create_database = true`, configures native RDS automated backups (`db_backup_retention_period`, module default 7 days, 0 disables backups) and optional restore from a snapshot (`db_snapshot_identifier`). With `create_elasticache = true`, configures daily ElastiCache snapshots (`redis_snapshot_retention_limit`, module default 1 day, 0 disables snapshots). | Restore drills, cross-region snapshot copy, Redis restore, S3 versioning policy, and backups for an external database or Redis are not provided. The module explicitly skips S3 bucket versioning (see the `CKV_AWS_21` exception in `s3.tf`) because n8n prunes execution data itself and versioning would only pile up noncurrent versions. The `n8n_encryption_key` output is a sensitive output stored in state and readable at any time (for example with `terraform output -raw n8n_encryption_key` when the root module re-exports it); it is null when `n8n_encryption_key_secret_ref` is set. Backing the key up outside Terraform state is the operator's job, because losing it makes every stored credential unreadable. | `db_backup_retention_period`, `db_snapshot_identifier`, `redis_snapshot_retention_limit`; README [Out of scope](../README.md#out-of-scope) |
| Upgrades and migration rollback | Supports bumping `n8n_image_tag` / `n8n_chart_version` on an existing deployment, with per-version upgrade notes. | Database migration rollback on a failed upgrade is not automatic. To roll back, stop n8n and either run `n8n db:revert` once per reversible migration, or restore the database backup taken before the upgrade (an RDS snapshot, or the external database's own backup). Some migrations are irreversible; check the release notes. | [`docs/upgrading-n8n.md`](./upgrading-n8n.md) |
| Monitoring and alerting | Wires n8n's Prometheus metrics endpoint (`n8n_metrics_enabled`) and an optional `redis_exporter` (`redis_exporter_enabled`) when the caller configures them. | The module installs KEDA and metrics-server because they are load-bearing for autoscaling, but does not install Prometheus, Grafana, Loki, OpenSearch, Datadog Agent, or any log shipper, and creates no CloudWatch alarms or dashboards beyond the CloudWatch log groups it already manages for EKS and RDS. Scrape configuration and alerting are the caller's monitoring stack. | `n8n_metrics_enabled`, `redis_exporter_enabled`; README [Out of scope](../README.md#out-of-scope) |
| Support boundary | Open source, maintained by the n8n Solutions team. | n8n's enterprise Support offering does not cover this module. | README [Support](../README.md#support) |

This page does not repeat the per-layer contract for caller-managed
infrastructure. See the README's
[Customer-managed infrastructure](../README.md#customer-managed-infrastructure)
table for that.
