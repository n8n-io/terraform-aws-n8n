# Shared responsibility

This module creates and configures an opinionated slice of AWS
infrastructure for n8n: EKS, an ALB Ingress, an RDS PostgreSQL instance,
ElastiCache Redis, an S3 bucket, and the n8n Helm release. It does not, and
is not intended to, run the whole platform for you. This page collects the
ownership boundaries that are otherwise scattered across the README's "Out
of scope" and "Support" sections, individual variable descriptions, and
several other docs, into one table so a platform partner pricing a build on
top of the module can find every gap in one place.

Read this alongside
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md)
and the README's [Customer-managed infrastructure](../README.md#customer-managed-infrastructure)
table, which document the caller-managed *layers* (EKS, S3, namespace,
Secrets, KEDA, worker fleet) this module can hand off entirely. The rows
below cover responsibilities that exist regardless of which layer ownership
mode is selected.

| Area | What the module does | What the caller owns | Related input / doc |
|---|---|---|---|
| Cluster security add-ons and policy | Creates the EKS cluster (or attaches to an existing one), its node group, envelope-encrypts Kubernetes Secrets with a Customer Managed KMS key by default (`eks_secrets_encryption_enabled`), and lets the caller restrict or disable the public API endpoint (`cluster_endpoint_public_access`, `cluster_endpoint_public_access_cidrs`, `cluster_endpoint_private_access`). | GuardDuty EKS Runtime Monitoring, Security Hub, and Pod Security admission policy are not enabled by the module and must be turned on separately (e.g. via `aws guardduty`/`aws securityhub`, or a `kubernetes_*` policy resource outside this module). The public endpoint is reachable from `0.0.0.0/0` by default; narrow or close it with the inputs above. | `eks_secrets_encryption_enabled`, `cluster_endpoint_public_access`, `cluster_endpoint_public_access_cidrs`, `cluster_endpoint_private_access`; [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md) |
| Network egress and DNS | Uses a caller-provided VPC and subnets (VPC creation is explicitly [out of scope](../README.md#out-of-scope)); when `create_ingress = true`, creates an ALB Ingress with a public or internal frontend; and when `route53_zone_id` is set, issues the ACM certificate and creates the Route 53 alias record(s) itself. | No NAT gateway, egress firewall, or VPC endpoint is created, outbound traffic from the cluster depends entirely on the VPC the caller brings. With a caller-supplied `certificate_arn` instead of `route53_zone_id`, DNS and certificate issuance are the caller's responsibility; see `examples/cloudflare/` and `examples/godaddy/` for that path. DNS resolution for an externally supplied PostgreSQL or Redis endpoint (`create_database = false` / `create_elasticache = false`) is also the caller's. | `route53_zone_id`, `certificate_arn`; [`examples/small/`](../examples/small/), [`examples/cloudflare/`](../examples/cloudflare/), [`examples/godaddy/`](../examples/godaddy/) |
| Secrets and Terraform state | Generates the RDS admin password (`random_password.db_password`) when `create_database = true`, the n8n encryption key, the ElastiCache AUTH token when `redis_transit_encryption_enabled = true`, and the task-runner token, as Terraform-managed values. | Every generated or caller-supplied value the module does not receive through a `*_secret_ref` lands in Terraform state on the default path: `random_password.db_password`, `db_password` when `create_database = false` and `db_password_secret_ref` is unset, `n8n_encryption_key`, `n8n_license_key` when `n8n_license_key_secret_ref` is unset, `random_password.task_runner_token` (always module-generated, no secret-ref alternative), `random_password.redis_auth_token` when `create_elasticache = true`, and `redis_auth_token` when `create_elasticache = false` and `redis_auth_token_secret_ref` is unset. Securing the Terraform state backend (encryption at rest, restricted access) is the caller's responsibility in every mode. Route the license key, encryption key, credentials-overwrite payload, external database password, and external Redis AUTH token through `n8n_license_key_secret_ref`, `n8n_encryption_key_secret_ref`, `n8n_credentials_overwrite_secret_ref`, `db_password_secret_ref` (external database path only, `create_database = false`), and `redis_auth_token_secret_ref` (external Redis path only, `create_elasticache = false`) to keep those specific values out of state. | [`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md); README [Secrets](../README.md#secrets) |
| Backup and restore | Configures native RDS automated backups (`db_backup_retention_period`, defaulting to RDS's own defaults) and optional restore from a snapshot (`db_snapshot_identifier`). | Restore drills, cross-region snapshot copy, S3 versioning policy, and backup for ElastiCache Redis are not provided, the module explicitly skips S3 bucket versioning (see the `CKV_AWS_21` exception in `s3.tf`) because n8n prunes execution data itself and versioning would only pile up noncurrent versions. The `n8n_encryption_key` output is emitted exactly once at apply time; backing it up is the operator's job. | `db_backup_retention_period`, `db_snapshot_identifier`; README [Out of scope](../README.md#out-of-scope) |
| Upgrades and migration rollback | Supports bumping `n8n_image_tag` / `n8n_chart_version` on an existing deployment, with per-version upgrade notes. | Database migration rollback on a failed upgrade is not automatic, n8n's own migrations run forward-only, so a caller who needs to roll back a bad upgrade restores from an RDS backup taken before the upgrade. | [`docs/upgrading-n8n.md`](./upgrading-n8n.md) |
| Monitoring and alerting | Wires n8n's Prometheus metrics endpoint (`n8n_metrics_enabled`) and an optional `redis_exporter` (`redis_exporter_enabled`) when the caller configures them. | The module installs KEDA and metrics-server because they are load-bearing for autoscaling, but does not install Prometheus, Grafana, Loki, OpenSearch, Datadog Agent, or any log shipper, and creates no CloudWatch alarms or dashboards beyond the CloudWatch log groups it already manages for EKS and RDS. Scrape configuration and alerting are the caller's monitoring stack. | `n8n_metrics_enabled`, `redis_exporter_enabled`; README [Out of scope](../README.md#out-of-scope) |
| Support boundary | Open source, maintained by the n8n Solutions team. | n8n's enterprise Support offering does not cover this module. | README [Support](../README.md#support) |

This page does not repeat the full ownership contract for caller-managed
EKS, S3, the namespace, Secrets, KEDA, or the external worker fleet, see
[`docs/customer-managed-infrastructure.md`](./customer-managed-infrastructure.md)
for those.
